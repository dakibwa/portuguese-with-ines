## 2. How to release

1. Build what you include from §4. Release 2 can also go first without §4.
2. Run the checks:
   - `npm run check:fast`;
   - the production build (`NEXT_PUBLIC_BOOKING_API_BASE_URL=http://localhost:8787 NEXT_PUBLIC_STRIPE_EXPECTED_MODE=live NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_live_local_qa_placeholder npm run build`);
   - the 12 journeys CI runs (`.github/workflows/deploy-pages.yml` ~146: qa-flow, qa-workspace-navigation, qa-booking-selection, qa-payment-recovery, qa-teacher-calendar, qa-transition-kit, qa-meet-links, qa-student-nif, qa-profile-rates, qa-request-recovery, qa-auth-recovery, qa-selection-calendar-recovery) against a local `wrangler dev` Worker on 8787 and the export on 3000.

   Some containers print dates as "Tue, 8 Sept" where CI prints "Tue 8 Sept". That comma alone is not a failure.
3. **Apply migration 0028 by hand** to staging (`ines-booking-staging`, `b4b5af8e-2fdc-4ea9-a5e7-0cc91688fc0f`) and then production (`ines-booking`, `e61786c2-f195-4087-b276-5f20bf64c429`). `d1_migrations` is empty, so do not use `migrations apply`. Run the file:

   ```sql
   ALTER TABLE bookings ADD COLUMN student_changed_at TEXT;
   ```

   First check it isn't already there: `SELECT name FROM pragma_table_info('bookings') WHERE name = 'student_changed_at'`. It is additive. The Worker tolerates the column missing, but student changes only show in Needs you once it exists. Record the date in `docs-booking-system.md`.
4. Open a PR into `main` and merge it. The release workflow tests and deploys the booking Worker first (`DEPLOY_WORKER` is on), then runs the journeys against the build, then publishes Pages. Watch the run; it takes about 8 minutes.
5. Once it is green, every student with a confirmed lesson 14–24 h away starts getting reminders within the minute. Nothing else needs switching on.

### 4.1 Timetable day headings: one tight box per day (Dan, 14 Oct)

Dan: "even this feels a little ugly right the text can be more tightly and better
displayed in the top of each day?" and "day off could be in the same box".
Today each column stacks `MON` / `7` / `TODAY`, a lesson dot sits under the date,
and a separate row of "Day off" switches sits below the headings.

**Build:**
- **One header cell per day**, holding everything:
  - weekday and date on **one line**, `Mon 7`: the weekday in the small caps label style, the date in the bold number style, baseline-aligned;
  - "Today" shown by the date in a small filled blue lozenge (cream number), not a third line;
  - the booked-lesson dot inline after the date.
- **The Day off switch inside the same cell:**
  - on wide columns, right-aligned on the same line;
  - when the column is too narrow (≤ ~120px), on a second short line within the cell.
  - Keep its accessible name (e.g. "Mon 7 September: day off") and a 44px hit area.
- **Delete the separate Day off row.** The time grid starts right under the headings.
- **The phone day selector** (one day shown) uses the same compact heading, with the switch beside it.
- **Keep** the `PORTO` corner label and alignment with the time column.
- **Update the docs and checks:**
  - `design/README.md` (teacher schedule, the week grid);
  - `scripts/qa-teacher-calendar.mjs` selectors for the switches.
- **Acceptance:**
  - at 1280, 1024, 844×390 and 390, heading plus switch is one compact band;
  - nothing wraps awkwardly;
  - Today is obvious;
  - the switches still work and are keyboard reachable.

### 4.4 "Needs you" as its own tab (Dan, 14 Oct)

Dan: "Can the needs you be a whole tab too of tasks that Ines needs to do like if it's
add an email for a user etc? that seems like a given that all users need an email
and need to add their card so she can monitor progress?"

**Design (decided):**
- **Tab:** a new `Needs you` tab, first in the bar, before `Timetable`.
  - It shows a small count of **her** to-dos (not of waiting-on-students items) in the coral dot style; no count at zero.
  - The phone tab grid gains the eighth tab; keep two rows and no scroll.
- **Section 1, "To do":** her actions, each a card with one button, newest-relevant first.
  - Everything the Timetable strip lists today, from `needsYou()` in `src/lib/teacher-calendar.ts`: Meet reconnect, payments to check, a new student's first lesson, welcome owed, and student changes and cancellations.
  - **Add their email:** every student with no email (`email === ""`), button "Add email", opening their profile with Edit details open.
  - **Send welcome email:** every student with an email who is `awaitingWelcome`, any time, not only within 7 days of a lesson. Coral button; keep `onlyIfWaiting: true`.
- **Section 2, "Getting started":** students not yet fully set up, one compact row each.
  - Name and splat, then four small steps that fill as they complete:
    1. **Email:** has an email.
    2. **Welcome:** welcome sent (`!awaitingWelcome`, or they booked themselves).
    3. **Signed in:** `signedIn`.
    4. **Card:** `hasCard`.
  - Steps are painted dabs: filled when done, outlined when not. The next step is labelled "Theirs" when it waits on the student (sign in, add card) or "Yours" when it's hers (email, welcome).
  - **Action:**
    - when the next step is hers, the same button as in To do;
    - when it waits on them, a quiet lilac "Send the link again". This calls the existing `POST /admin/students/:id/welcome` **without** `onlyIfWaiting`. The endpoint already sends a fresh sign-in link and is rate-limited to 3 an hour; show its 429 message as is.
  - A student leaves the section when all four steps are done.
  - Clicking the row opens their profile.
- **Empty states:**
  - "Nothing needs you right now." for To do;
  - Getting started is simply absent when everyone is set up.
- **Timetable strip:** keep it, but show at most 3 items, plus "See all in Needs you" (a text button switching tabs) when there are more.
- **No Worker change:** all from `GET /admin/students` (email, awaitingWelcome, signedIn, hasCard, nextLessonAt) and the reads Needs you already makes. Permission path unchanged.
- **Docs and tests:**
  - extend the pure selector with unit tests in `scripts/test-teacher-calendar.mjs`: the steps, Yours/Theirs, ordering and the count;
  - one step in `qa-teacher-calendar` opens the tab;
  - update `design/README.md` (teacher schedule: tabs, Needs you).
- **Acceptance:**
  - at 1280 and 390, To do and Getting started read at a glance, nothing stranded, and the count matches To do;
  - "Add email" lands in the profile's details editor;
  - "Send the link again" never sends to a student without an email.
